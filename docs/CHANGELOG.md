## v0.5.2 (2026-10-27)

- 修复 TUN / 代理模式下任务栏网络延迟长期显示 `1ms`：原始 ICMP 回包可能为 `0ms`，旧版将其强制改为 `1ms`；TCP 本地握手也无法代表经代理完成外网请求的耗时。
- 将连通性心跳和显示延迟分开。每 5 秒通过系统代理/TUN，独立测量到 `https://www.cloudflare.com/cdn-cgi/trace` 的 HTTPS GET 请求耗时，包含 DNS、建连、TLS 与响应头。
- 请求失败或采样超过 15 秒时显示 `--`；出口切换后取消旧测量并丢弃迟到结果。连通性旁证不再沿用旧心跳 RTT。
- 悬停提示和诊断面板显示测量方式、目标、采样时间及错误。移除 ICMP/TCP 的最小 `1ms` 强制取整。
- 补充失败/过期/出口切换回归测试，并更新根目录运行副本、验证记录和使用说明。

## v0.4.1 (2026-10-26)

- **修复 TUN / 代理虚拟网卡模式下网络状态在「正常 ↔ 待确认 ↔ 断网」间循环误报的 Bug**：
  1. **同周期双 IP 即时复核 + TCP 443 握手兜底（[`network_windows.go`](../internal/network/network_windows.go)）**：当主目标 `1.1.1.1` 的三层 ICMP Echo 被 TUN 驱动偶发丢弃或提前返回 `11010` 时，不再跨秒等待，立即在同一周期对备用目标 `8.8.8.8` 发起复核；若两次 ICMP 均失败，立即发起轻量 TCP `443` 端口握手探测（超时 500ms，连接建立即关闭）并测量 TCP 握手耗时作为 RTT。
  2. **活跃下行流量与 HTTPS 通信旁路在线证明（[`engine.go`](../internal/app/engine.go)）**：当探针偶发超时但当前网卡存在真实下行流量（`> 512 B/s`）或最近 4 秒内行情/定位 HTTPS 请求刚刚成功返回时，直接确认在线。
  3. **状态机防抖阈值优化（[`state.go`](../internal/monitor/state.go)）**：已处于 `Online` 状态时，单次失败保持 `Online` 不闪黄灯；连续 2~3 次失败才进入 `Degraded`（待确认）；连续 4 次及以上失败才触发 `Offline`（断网警告）。
  4. **路由/IPv6 地址刷新事件无感过渡（[`engine.go`](../internal/app/engine.go)）**：收到系统路由或 IPv6 临时地址变动通知时，若当前已在线，不再清空状态与出口国家代码，仅在后台静默复核出口 IP。
